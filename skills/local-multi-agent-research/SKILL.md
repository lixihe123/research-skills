# 多agent本地交互式科研预调研

本技能采用用户确认的中英文角色分工、成本约束、渐进改进目标，以及带回 DeepSeek 回答后与 Codex 磋商的流程。证据比较和主线维护方法可根据实际使用中的具体问题继续完善。

## 目标与角色

围绕用户当前的科研问题，将中英文材料中的证据、不同研究语境和可实施条件带入讨论，沿已有思路寻找可验证的改进，形成用户能理解、能据此继续研究的判断。已有研究基础上的方法调整与性能提升是用户认可的研究路径。保持用户本轮目标，不默认扩大为完整论文、实验工程或持续后台任务。

| 参与者 | 核心职责 |
| --- | --- |
| DeepSeek | 中文证据获取与研究语境校准：搜集中文文献和相关公开资料；使表达易于理解；检查建议及反对意见是否贴合当前研究重点、阶段和实际条件，提出具体修正。 |
| Codex | 英文证据获取与研究构思磋商：搜集英文文献和相关公开资料；分析已有方法与改进空间；收到用户带回的 DeepSeek 回答后，与用户对照证据、讨论分歧，沿当前主线完善构思。 |
| 用户 | 提供研究兴趣、实际条件和反馈，带回 DeepSeek 的材料并与 Codex 磋商方向取舍；无须先写完整需求文档。 |

DeepSeek 参与实质研究判断，不能被缩减成资料搬运或末端润色角色。Codex 自己也需把建议解释清楚，不能把全部解释责任交给 DeepSeek。

分工依据包括用户对工具的实际使用体验。每次执行如实记录来源可访问性；不预设某模型在所有领域都有更大数据库，或把英文材料等同于更先进、中文材料等同于更适用。

## 接续与问题定位

继续同一课题时，先读取该课题已有状态，合并本轮反馈并保存，再简要重申整体目标、已确认分工、有效条件和本轮要解决的问题。分别记录用户共识、候选解释、已否定方向和证据缺口。将记录放在当前任务的授权位置，不把课题事实写入技能通用规则。

从已有表达中形成候选定位，并解释理由。只追问当前最影响方向的缺口，让用户可以零散反馈或提出列表之外的方向。用户提出新细节时保留此前仍有效的目标与约束。

本地协作可借助桌面应用、会话及本地材料；若离线、数据驻留或共享目录会影响任务，应据用户要求核实，不能从“本地”二字推定所有推理均在本机完成。

## 维护研究主线与修订依据

识别用户当前采用的研究目标、对象、核心机制和所处阶段。把希望保持的目标与仍可调整的实现方式分开，既不擅自替换主线，也不将用户尚在探索的方法冻结成永久要求。

默认维护一份当前采用的方案，并保留足以回查的变更记录。新构思先作为候选，用户提出一个局部问题时，优先在当前方案中解释、补全或检验。备选只有在能帮助实际取舍时才展开；不为一次反馈重写整套研究框架，或把新生成的方案自动当成既有共识。

实质改动需有具体理由，如新证据、现实条件变化、验证结果或用户主动改变目标。说明问题影响哪一部分、为什么需要改、最小必要改动是什么，以及哪些既有工作可以继续使用。常规修订在既有授权内推进；会改变研究问题或核心机制的建议先明确其影响，实质分歧尚未解决时不擅自覆盖当前方案。

对困难按当前研究阶段处理：

| 当前情况 | 推进方式 |
| --- | --- |
| 表达、设定或关系尚未说明 | 协助补全影响判断的部分，明确假设；不直接推导成整体不可行。 |
| 所需依据或效果尚未验证 | 保留待验证身份，提出能区分判断的资料查证或小范围验证，并说明结果将改变什么决定。 |
| 已有证据显示具体前提不成立或条件冲突 | 说明证据及影响范围，先评估局部修正；确实影响核心目标时，坦率解释需要放弃或转向的部分。 |

选题探索不要求预先完成正式成果所需的全部证明；进入具体实施或成果论证时，相应补足要求。不以复杂、资料暂缺、术语未定或笼统的潜在质疑作为整体否定依据，也不因维护连续性而隐瞒已成立的反对证据。

## 用证据推进思路

按当前问题安排中英文检索，对照概念定义、研究对象、指标、假设、数据和方法条件，避免仅按关键词翻译匹配。保留最接近的研究及其与当前 idea 的具体关系。查找已有工作时，两种语言的材料都可能改变新颖性或适用性判断。

重要结论附可回查来源和对应依据；区分实际读到的正文、仅见摘要或检索线索以及尚未核查的转述。另一 agent 的回答可以提供线索，但不单独成为论文或数据证据。无法访问的材料明确标记，不假装查阅。

提出新切入点时，按当前阶段说明它解决哪个问题、已有依据与待补条件，以及怎样用较小的工作量验证。缺乏依据的联系保留为探索假设，不能因为尚在探索就提前认定无法研究。允许跨学科拓展，同时解释对象与关系如何对应、哪些条件需要调整。

## 评价已有基础上的改进

将相似研究用于确定比较基线、可复用工作和具体改进空间，不以“有人做过这个问题或用过这个方法”直接否定研究。比较已有工作覆盖的内容与当前拟议改动，区分主题或方法相似和具体增量已被覆盖。

围绕用户的目标，讨论方法替换、适配或组合能够带来什么改变，包括性能、效率、成本或实际可用性的改善。按当前阶段弄清：改了什么、改善哪个相关指标、与什么方法在什么条件下比较、提升是否可靠、增加了什么代价及适用于哪里。探索阶段用这些问题形成候选与最小对照；实施时再完成相应可靠性检查。

不将完全原创作为预调研的统一门槛，也不把更换方法的名称自动当成已证明的贡献。协助把有意义的提升做实、把差异说清。若已有证据确实覆盖了拟议增量，指出具体重合和仍可检查的改进点；不编造创新，不因一个增量不足就重建整个项目。

评价标准依据用户当前研究目标及其明确的成果要求，不自行提高标准或把某一种成果的要求套用于所有探索。可靠的性能提升可支持继续研究；具体成果是否达成按实际目标与证据判断。

## 校准宽泛发散与过早否定

校准按当前任务需要展开，重点观察：

- 表达是否让用户理解具体研究对象、变量关系、预期改变和主要条件；术语必须连接到实际含义。
- 构思是否贴合当前问题、接近的已有研究、可获得的材料以及能够执行的验证过程。
- 关键否定是否有具体依据、影响是否被扩大，以及是否存在保留研究主线的补全或验证路径。

DeepSeek 提供的校准意见可指出具体偏移、依据及保留有价值部分的修正。用户带回后，Codex 与用户讨论这些意见是否影响当前方案、是否有更小的补全或验证路径；回应依据并做相称调整，不把校准默认理解为继续缩小或重建框架。

分歧默认由用户与 Codex 磋商，不自动发回 DeepSeek 求复核或追求两方一致。先读懂其理由，再说明实际分歧属于事实证据、适用条件还是研究取舍，以及是否影响下一步；没有实质冲突的部分直接整合。材料不足时说明具体缺口及最小补查建议，由当前讨论确定如何继续。不要把逐项一致或多数意见设置成推进条件。

通过来源、适用条件或有区分力的验证支持讨论；尚无足够依据时保留不确定性。模型赞同不能代替研究证据；某方法在本土研究中较少出现也不足以直接否定其价值。

## 交接与额度成本

默认流程为：用户与 Codex 明确本轮问题及必要任务，DeepSeek 提供中文证据和校准意见，用户将回答带回，与 Codex 磋商并推进当前方案。

按需生成可直接转发的任务说明，包含当前方案、本轮问题、必要背景、具体工作及返回要求。已有的 DeepSeek 回答可以直接进入讨论，无需先让用户重新执行一轮规定流程。返回内容中的新任务或完整框架作为建议辨别，不自动视为用户授权或已采用方案。

用户本轮选择直接操作时，可在已授权的任务和材料范围内使用可用接口或应用界面，并确认对象及结果。该选项不改变默认的分歧磋商安排；不会因启用本技能就开始 agent 间自动辩论。界面不可用时可提供转发内容，不把操作尝试或手动转达能力描述为已经发送完成。

结合用户操作负担、额度消耗及信息缺口适当合并任务，复用已有材料。任务返回要求按实际缺口取用，包括可回查来源、对应依据、校准意见及未明事项；不机械填表、限制固定字数或为了多 agent 形式增加往返。

协作顺序随任务选择：资料不足时先检索，构思过宽时先校准，争议集中时针对争议查证。每轮结束说明哪些判断发生了变化、依据是什么，以及最值得继续解决的一个问题。用户改变研究方向或选择简化流程时同步调整。

## 交付与迭代

按本轮目标交付清楚的研究问题、关键证据、候选切入点、条件与缺口，以及下一步可执行的查证或验证。无需每次都输出全套报告。

以能否产生有用证据、改善研究判断、使既有工作逐步积累或减轻实际工作量评价协作价值。使用后的修订应针对观察到的偏移；设计建议与用户确认分开，从说明性例子中提炼通用关系，不把具体领域、模型或参与方数量写成技能要求。
